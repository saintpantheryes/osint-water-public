# 用 Teable 做部门共用的多维表格(自托管)

这套文件把 [Teable](https://github.com/teableio/teable)(开源多维表格,AGPL 社区版)装到一台自己的云主机上,
配 Caddy 自动申请 HTTPS 证书,手机微信里直接打开。监测系统每天把线索和台账写进去(`python -m core.cli teable`),
同事在表格里筛选、改状态、写跟进。

## 准备

- 一台公网云主机(2 核 4 GB 起,Teable 官方最低要求),root 密钥能登录。用中国内地节点必须 ICP 备案,
  国外后缀域名备不了案,所以选香港或海外节点。
- 一个域名的子域名(例如 `water.example.uk`),DNS 在 Cloudflare。
- 云主机安全组放行 TCP 22(你的 IP)、80、443。

## 安装(在 Mac 上,三条命令)

```bash
cd <程序目录> && git pull
bash deploy/teable/push_from_mac.sh ~/Downloads/<密钥>.pem <主机IP> water.example.uk
```

脚本会把本目录复制到主机的 `/root/teable-kit`,在主机上装 Docker、起 Teable + Postgres + Redis + Caddy,
注册管理员、生成接口令牌、关掉自助注册、配每日备份,最后把凭据打印在你的终端(主机上存于 `/opt/teable/ADMIN.txt`,只有 root 可读)。

如果主机镜像自带宝塔并且已经装了 nginx 占着 80/443,脚本会停下来提示;确认不用宝塔的网站功能后:
`FORCE_STOP_WEB=1 bash deploy/teable/push_from_mac.sh ...`。

脚本可以重复运行:装好的部分会跳过。若第 5 步(注册管理员)半途失败、密码没保存下来,而库里还没有数据,
用 `RESET_DB=1 bash deploy/teable/push_from_mac.sh ...` 清空 Teable 数据重建。

然后:

1. Cloudflare → DNS → 加 A 记录:名称 `water`,指向主机公网 IP,**代理状态选「仅 DNS」(灰云)**。
   橙云代理经 Cloudflare 边缘节点回源,内地访问经常变慢甚至打不开。
2. 等一两分钟,打开 `https://water.example.uk`。证书由 Caddy 自动签发;没起来就看 `cd /opt/teable && docker compose logs caddy`。
3. 用 ADMIN.txt 里的邮箱、密码登录,先改密码;再在「空间」里生成邀请链接发给同事(自助注册已关闭)。

## 接上监测系统

- GitHub 仓库 → Settings → Secrets and variables → Actions,加两个 secret:
  `TEABLE_URL = https://water.example.uk`、`TEABLE_TOKEN = <ADMIN.txt 里的接口令牌>`。
  之后每天监测之前把表格里的改动拉回、自动入账之后推送;没配时这两步跳过。装了系统(见下文"系统")、profile 的
  `teable.server_sync` 打开时,改由**服务器上的系统每 30 秒同步一次**,定时任务里这两步只打一行"由服务器同步"就跳过
  (secret 还要留着:表格从备份恢复后的对齐要用)。
- Mac 上手动同步:程序目录的 `.env` 里加同样两行,然后推送 `python -m core.cli teable --profile private/profile.yaml`、
  拉回 `python -m core.cli teable --pull --profile private/profile.yaml`。
- 库名写在 profile 的 `teable` 节(不写时取缺省):
  ```yaml
  teable:
    base: 水务项目机会   # 库名,按名找;没有就在令牌能看到的第一个空间里建
    pull: true           # 把同事在表里改的人管字段拉回系统;缺省 false
    internal_reports: false  # 「报告」表是否也传含内部信息的报告(月报内部版、国别动态、线索简报);缺省只传周报与月报公开版
    notify_owner: false      # 同事被设为负责人时站内通知本人(推送时打开「负责人」字段的通知);缺省不动这个开关
  ```
- 第一次同步会建这个库和五张表(见下一节)及视图;以后只增量更新,新加的表、字段、视图下次同步时补上,已有的不动。
  同事在表里改的处理状态、跟踪进展、负责人、下一步、备注、结果原因(线索表)与进展、优先级、负责人、下一步、内部备注(商机表)不会被同步覆盖
  (本机改了、表格里没人改过的才写回,见"本机的改动怎么到表格")。

## 后台任务(worker,阶段 D)

新版没有网页程序:同事直接用表格,后台任务(worker)在表格所在的主机上常驻,用**机器账号**的令牌往新库(「… 新版」)写
([架构方案](../../docs/架构方案_2026-10-03.md) 第 4 节)。它做的事:每天北京时间 08:30 采集各信源、判定线索、
建议或更新商机、写时间节点;每 2 分钟把同事新建并填了原文网址的线索补全(标题、摘录、国别、摘要……,不判相关性),
并把人改的商机阶段记成一条跟进;每天零点后第一个周期把已过期的时间节点改为「已发生」(Teable 含 TODAY() 的公式隔天不自动重算,阶段 A 复核 2026-10-04 定论,改状态才会触发「未过截止」「最近截止」「下一节点」重算;页面与报告里的日期窗口都按当天自己算)。写的规矩(只填空、列表只追加、不同的写进「待核更新」)在 core/tstore.py 与 core/jobs/。

**两个仓库**([docs/PUBLISHING.md](../../docs/PUBLISHING.md)):公开核心仓 = 程序(本仓库),私有配置仓 = profile、市场分布表、岗位代号表、
报告模板、页面配置 `portal/config.json`。主机上各一个检出:`/opt/osint-water`(核心)与 `/opt/osint-water-private`(私有);compose 把私有检出
挂成程序里的 `private/`,把 `portal/config.json` 挂到页面目录。本机开发同理:把私有配置仓检出(或软链接)到核心仓检出的 `private/`。

安装(在 Mac 上、在核心仓的检出里,两条命令;可重复运行):

```bash
bash deploy/teable/worker_token_from_mac.sh ~/.ssh/<密钥>.pem <主机IP>   # 粘贴机器账号的令牌(只做一次;管理员令牌不上主机)
bash deploy/teable/worker_from_mac.sh ~/.ssh/<密钥>.pem <主机IP> <所有者>/<私有配置仓>   # 第一次要给私有配置仓;主机会记住,以后可省
```

- 第二条脚本会打印主机生成的部署密钥(公钥),按提示加到 GitHub **对应仓库**的 Deploy keys(只读即可;两个仓库各一把——私有配置仓用的
  是拆分前那把,GitHub 上已登记,一般只需给核心仓加新的),然后在终端粘贴模型密钥(DeepSeek 或 Claude;不给就只用规则初筛)和可选的
  告警心跳网址(healthchecks.io 之类)。密钥都写在主机 `/opt/teable/worker.env`(只 root 可读),不进仓库。
- 每天北京时间 08:00 `worker_update.sh` 取两个仓库 main 的新提交并重启,依赖清单变了会重建镜像。缓存(网页正文、各信源已见条目)
  在 Docker 卷 `worker-cache`,删了也只是重抓一遍。
- 看状态:`ssh -i <密钥> root@<主机IP> bash /opt/teable/worker_install.sh status`;看日志:`cd /opt/teable && docker compose --profile worker logs -f worker`。
- 手动跑一个任务(在主机上):`cd /opt/teable && docker compose --profile worker run --rm worker python -m core.cli run collect --profile private/profile.yaml`
  (任务名:collect 采集与判定、suggest 补做建议、enrich 补全上传、stage-log 阶段记跟进)。
- 报告:同事在「报告」表新建一行,选类型(国别报告选范围国别,项目报告选范围商机;周报、月报填期间如 2026-W40 / 2026-09 或留空),生成状态留「待生成」,
  2 分钟内生成 Word 传到「文件」。周一 09:00 自建上周周报、每月 1 日 09:30 自建上月月报。模型配好时带分析段落,没配只出数据章节。
- 日报(每日简报):每天 08:30 采集完成后自建当天一行并生成,几百字的中文统计简报(今日新增与分布、值得看的新线索、商机动态、信源运行),
  正文写进「简报正文」列并显示在页面「线索分析」顶部,Word 在「文件」里;没配模型也能出,配了多一段「模型研判」。补要某一天的:报告表新建一行,
  类型选日报、期间填 YYYY-MM-DD。**升级到这版后管理员跑一次 `python -m core.schema --profile private/profile.yaml`**:它给报告表补「简报正文」列、
  给「类型」「适用类型」补「日报」选项(表格锁了自动加选项,后台写不进去),并重写 private/portal/config.json(页面要用新列的编号)。
- 国别信息:每月 1 日按世行、IMF 接口刷新指标与收入组,新国别出现后第二天补齐;机构、国企、法规只追加,市场分级等人管的列不动。
- 首页与登录页的背景动画:原首页视频转成的「字符动画」。私有配置仓 `portal/media/` 下放 `hero_ascii.jpg` + `hero_ascii.json`(帧图:
  `python3 scripts/ascii_sheet.py hero.mp4 portal/media/` 从视频生成,112×49 格、10 帧/秒、约 0.6 MB;原来 10 MB 的 `hero.mp4`、`hero.jpg` 可以删),
  compose 把该目录只读挂到页面目录的 `media/`;页面脚本 `portal/ascii-water.js` 按格子取颜色、亮度写字符。没有帧图时画一张字符世界地图。
- 助手(首页的提问框):后台任务进程里另起一个线程跑助手接口(`core/assistant_server.py`,容器内网 `worker:8765`,不对外开端口;
  环境变量 `ASSISTANT_PORT` 改端口,0 不起),Caddy 把 `/portal/api/assistant/*` 转过去(`portal.caddy`,登录检查在前)。接口只把一句提问翻成
  筛选条件(国别、领域、类别、资金来源、阶段、时间、关键词),页面带着登录人的 cookie 自己查表格并呈现,模型看不到表里的数据。配了模型密钥时由
  模型解析(沿用 `watch.llm` 的 provider / model,关思考模式,一问几百 token;profile 的 `assistant.llm` 可另选更便宜的模型,如
  `{model: deepseek-flash}`),没配时按词表解析(能认国名、领域、类别、出资方、时间、阶段这些词)。模型密钥两家都行:DeepSeek(`DEEPSEEK_API_KEY`,
  密钥 sk-…)或 Claude(`ANTHROPIC_API_KEY`,密钥 sk-ant-…),`worker_from_mac.sh` 按前缀分辨;用哪家由 `profile.yaml` 的 `watch.llm.provider` 决定。

- 日历订阅(.ics):日历页「下载 .ics」(登录后下载当前筛选的内容,苹果日历、Outlook 直接打开导入)与「订阅到日历」(给一条 webcal 链接,
  加到苹果日历 / Google 日历后自动更新,每 6 小时刷一次)。订阅链接不经登录检查、凭链接里的令牌(整个团队共用一串;环境变量 `OW_FEED_TOKEN`
  可指定,没设就按机器账号令牌派生,换了机器令牌链接就失效,要重新订阅),只含跟踪中商机的时间节点、跟进的下一步到期与国别级节点,
  不含内部备注。路由在 `portal.caddy`(`/portal/feed/calendar.ics` 转后台任务进程,其余 `/portal/*` 照旧先登录);代码 `core/calendar_feed.py`。

## 页面(portal,阶段 E、F)

静态页面,在表格同一个网址的 `/portal/`(根网址直接转过去;表格首页仍在 `/space`)。没登录先到登录页(自己的,见下面「登录页」)。
页面里的脚本带着登录表格的同一个 cookie 直接调表格接口,看到的就是这个人在表格里有权看的,写的也是以这个人的身份写(权限、历史都还是表格的);
没有令牌、没有服务器程序、没有数据副本。首页、日历、国别概况只读;商机工作台会写。表、字段、视图按编号取(`portal/config.json`,`python -m core.schema --config-only` 从库里只读生成),同事改字段名页面也不坏。

- **菜单**(各页入口与每页一句说明只在 `portal/portal.js` 的 `MENU` 一处,工作流程页的「各页是干什么的」也读它):首页;**工作原理**(工作流程、本体、后台数据表格);**项目线索**(线索总览、线索分析、线索处理、国别概况);**商机跟进**(商机总览、日历、报告)。
  电脑上的内页顶栏平铺「首页」与三个组名(点组名进这一组的第一页,当前页所在的组标蓝),顶栏下面一排页签是这一组的各页(鼠标停在页签上显示那一句说明;手机上横着滑,前面带组名);首页和手机上点「菜单」出白色卡片,三组分三栏(手机上下排)。「后台数据表格」就是表格本身(新窗口,游客不显示);「我的」「我方资料」在帐号区,商机工作台从商机总览点进,都不进菜单。
- **登录页**:`/auth/login` 是自己的页面(`portal/login.html`,Caddy 直接给,不经过表格的页面):左边系统标志、站名(中英)和首页同一段视频,右边邮箱、密码。
  登录仍走表格自己的接口(`POST /api/auth/signin`,同一个 cookie,帐号密码就是表格的),登录后回到网址里 `redirect` 指的本站页面(外站、登录页本身不认,回 `/portal/`);已经登录的打开它直接过去。
  「忘记密码」与邀请链接的「注册」仍是表格自己的页面(只在带着邀请链接来、或管理员开了注册时才露出「先注册」)。表格页面里的站内跳转(注册页点「登录」、在表格里退出)
  取 `/_next/data/…/auth/login.json` 时 Caddy 给 404,浏览器改成整页打开,也落到这一页。登录页要用的字体、标志、首页视频与封面不用登录也能取(`portal.caddy` 的 `@ow_open`,写死文件名),
  别的页面、配置、接口照旧要登录。回退:删掉 `portal.caddy` 里 `@ow_login`、`@ow_login_data` 两段,重载 Caddy,就是表格原来的登录页。
- **日历**:跟踪中的商机的时间节点、跟进(日期与下一步到期)、报告,按月看,可按国别、商机、负责人筛;点一条在表格里打开;「下载 .ics」「订阅到日历」见上。
- **工作流程**(菜单「工作原理」组,原名工作原理):一页说清主线(线索 → 商机 → 跟进 → 报告与日历,机器一栏、人一栏)、每天的节奏、谁做什么(按本体的行为现列)、几条底线(本体规则)、问答怎么回答、各页是干什么的(按菜单分组)。
- **线索总览**(菜单「项目线索」组,原首页、后改名总览):平铺的筛选按钮(区域(国别表「经营区域」的值,选区域后国别只列该区域的)、国别、业务领域(可多选)、类别、资金来源(出资方按机构族归组,规则在本体 groupings.funders)、时间),待办数字;左栏漏斗(信源 → 相关 → 属于商机 → 跟踪商机 → 写进报告)与世界地图(各国线索与商机,点国家进国别概况),右栏清单(点漏斗一级列出该级线索)与最新报告(可直接下载 Word)。
- **国别概况**:顶部一张世界地图(颜色深浅是线索数,点国家切换,当前国家描红边)与国别下拉(只列国名);国别信息、该国商机(按阶段)、最近 90 天线索、未来 30 天节点。
- **线索处理**(阶段 F,原「待我处理」):两个标签页带数字(线索归属待确认、AI 推荐的商机);归属页可按国别、类别、有无机器建议筛,勾选后批量归入建议商机 / 批量忽略;推荐页可批量跟踪 / 不跟进。原来的「下一步已逾期」「待核更新」两页挪到了商机总览(旧链接 `inbox.html#over`、`#review` 自动转过去)。
- **报告**:历史报告清单(按类型、版本、状态、国别筛,搜期间或商机,点文件名下载)、要一份国别报告或项目报告(进报告表排队,可选模板)、**报告模板**管理:上传 .docx(名称、适用类型、缺省)、换文件、设为缺省;删模板去表格。模板存在「报告模板」表里(附件),后台生成时下载套用:报告行选了的 → 该类型勾了缺省的 → 该类型任一个 → 程序自带的版式;实际用的填回报告的「模板」。
- **本体**(只读):系统里有哪些对象、它们怎么关联(图)、每个对象的属性与状态流转、每个选项的定义与边界、口径、规则、行为、版本记录,全部按 `portal/ontology.json`(`docs/ontology/ontology.yaml` 转的,`python docs/ontology/gen_json.py`)现显;本体改了页面跟着变。
- 正文里的出处 `[8位线索号]` 在商机工作台与国别概况里显示为带序号的小角标,点开是那条线索;页面底部列出角标对应的线索标题。
- **商机总览**(阶段 F,原「商机」):只算人确认跟踪过的商机(跟踪中、准备投标、已投标、中标、未中标、放弃;AI 推荐、不跟进的留在线索处理那一步,2026-10-16),三个页签——商机列表、下一步已逾期(跟踪中、下一步到期已过)、待核更新(机器发现的新值等人核;人驳回的 ✗ 行不算),后两页原在「待我处理」,游客不显示。商机列表顶上提醒「今天有 N 个商机有新线索」,名称后带「今日新线索 +N」/「近 7 天 +N」,「更新」筛选只看这些(2026-10-16)。商机列表(缺省只列跟踪中的;与首页同一套平铺按钮:阶段、区域、国别(前 10 + 更多国家)、领域(商机的 12 类细分,可多选)、资金来源(按商机「资金」每行开头的出资方归组)、负责人,再加搜编号名称;筛选写进地址栏)→ 每个商机一页的**工作台**:全貌(公开进度、下一节点、下一步、判断、资格)、
  跟进时间线、时间节点、机器整理的项目情况、所属线索、报告;页面上直接**记一笔跟进**(可顺手改阶段:跟进带「阶段变更」、商机阶段同步改,后台的阶段记跟进不会重复记)、
  **要一份报告**(项目报告或所在国的国别报告,进报告表排队,2 分钟内生成)、**我来负责** / 优先级 / 内部备注。页面只新建与修改,从不删;删记录去表格。

## 表格里的改动怎么回到系统(拉回)

每次同步时(服务器上每 30 秒;没开 `teable.server_sync` 时每天监测之前,`teable --pull`),系统读线索表、商机表的人管字段,与 `data` 分支 `watch/teable_state.jsonl`(每条记录上次同步时的值,只追加)比较,

|---|---|
| 线索的处理状态(待处理 / 已处理 / 已忽略)、备注 | 处理状态(`watch/triage.yaml`)与处理备注,记一条操作记录;只改了备注的记一笔 |
| 线索的跟踪进展 | 线索已属于商机的:改的是**商机的进展**(记在商机编号下,注明在哪条线索上改的),商机表跟着改;还没有商机的:操作记录里的进展,从没设改成跟踪中、准备投标、已投标、中标的,**跟踪即入账**(按线索建商机,推送 main) |
| 商机的进展、下一步、下一步到期 | 记在商机上的操作记录;进展清除即不再跟踪(下次推送商机表里删掉这一行,所属线索上以前设的进展一并清除) |

| 跟进记录表里新加的一行 | 商机的一次**跟进**(内容、判断与依据、跟进日期,带这一行的记录 ID),操作人记「人」:记在关联的商机上;只关联了线索的,记在线索所属的商机上(线索还没有商机的记在线索上)。填了进展的改商机的进展,判断为放弃又没填进展的进展记为放弃,填了下一步的记下一步。系统「商机」页的「跟进与判断」、商机表的「当前判断」「最近跟进」、日历与周报的「商机跟踪进展」都从这里来 |

| 跟进记录里删了一行 | 系统里那条撤回(操作记录记"撤回一条跟进"),推送时不再重建。整张表一下子空了不当作删除(推送时按系统里的重建);从备份恢复后丢了的行,对齐时记下,推送时重建 |

### 本机的改动怎么到表格(写回)

推送时(每天自动入账之后)按同步状态逐格比较:**本机自上次同步改了、表格里没人改过**的,把本机的值写进表格;
表格里有人改过的不覆盖,由下次拉回以表格为准(本机也改了的注明本机原来的值,见上)。

| 本机改了 | 写到表格 |
|---|---|
| 线索的处理状态与处理备注(监测页标记、商机或待确认页更新台账后标为已处理等) | 线索的处理状态、备注 |
| 线索的跟踪进展 | 线索的跟踪进展 |
| 内部叠加里项目的优先级(A/B/C)、内部备注(`private/overlay/<国别>.yaml` 的 `items.<编号>.priority`、`note`) | 项目的优先级、内部备注 |

- 负责人、下一步与到期只在表格里设,本机不写回(负责人是表格的成员字段)。
- 内部叠加里不是 A/B/C 的优先级表格里没有这个选项,不写,推送日志里提示。
- 早期的同步状态行没记本机当时的值的,那几项这次只补记、不写回,之后本机再改的照常写回。

## 通知(不用邮件)

- 「每日摘要」表每次监测一行:新增相关线索、14 天内截止、自动入账、信源异常,这次传上来的报告挂在这一行。手机上打开看最新一行。
- 被设为负责人时通知本人:Teable 自带站内通知(页面右上角的铃铛),不用邮件;自己设自己不通知。系统建表时「负责人」字段的通知
  是关的。profile 写 `teable.notify_owner: true`,下次推送时把线索表、商机表两个「负责人」字段的通知打开(也可以在表格里手动开:
  「负责人」列头 → 编辑字段 → "用户被选择后发送通知")。写了 true 以后,表格里关掉的下次推送又会打开;要关,先把 profile 改回
  false 再在表格里关。
- 记录的评论里 @同事,对方同样在铃铛里收到提醒;在某条记录下评论过的人,这条记录有新评论也会收到。
- 邮件:Teable 社区版没有"自动化"(企业版功能,界面里只显示升级提示),"每日摘要新增一行 → 发邮件给团队"在表格里做不了。以后要邮件:
  - 在主机的 `/opt/teable/.env` 加 SMTP:`BACKEND_MAIL_HOST`、`BACKEND_MAIL_PORT`(缺省 465)、`BACKEND_MAIL_SECURE`(缺省 true)、
    `BACKEND_MAIL_SENDER`、`BACKEND_MAIL_SENDER_NAME`、`BACKEND_MAIL_AUTH_USER`、`BACKEND_MAIL_AUTH_PASS`,然后
    `cd /opt/teable && docker compose up -d`。上面两种站内通知就同时发邮件(各人可在个人设置的通知里关掉邮件)。
  - 每日摘要要发邮件,得在定时任务(`.github/workflows/monitor.yml`)里另加一步由 GitHub 发,表格做不了。

## 日常与运维

### 每天自动

- 定时任务(monitor)开头检查表格在不在线(`<地址>/health`)。表格连不上、拉回或推送出错时,监测照常做完、结果照常提交,
  最后一步「团队表格没同步成时提醒」把这次运行标为失败,GitHub 按通知设置发邮件;原因看「检查团队表格」「从 Teable 拉回」
  「同步到 Teable」三步的日志。
- 系统(装了的话):每天北京时间 09:30 取 main 的新程序并重启(`/opt/teable/app_update.log` 每天一行);新数据每 5 分钟自动取。
- 备份:每天 03:30(主机时间)把数据库和附件打包到 `/opt/teable/backups/{db,assets}-<日期>-<时分>.*`,保留 14 天;手动多备份
  一次另成一份,不会盖掉定时的那份。文件的修改时间就是开始备份的时刻(恢复后要填的"备份时间")。`/opt/teable/backup.log` 每次
  一行"备份完成";出错写 ERROR(之前的备份不受影响),磁盘剩余不到 2 GB 写 WARNING。

### 例行检查与恢复演练(每月一次,或动过主机之后)

在 Mac 上一条命令,不动线上的表格与数据:

```bash
bash deploy/teable/check_from_mac.sh ~/.ssh/<密钥>.pem <主机IP>
```

它把主机上的备份、恢复演练、恢复三个脚本换成仓库里的新版,列出备份日志、定时任务、磁盘和最近的备份文件,现在备份一次,再用
这份备份在临时数据库里恢复一遍(`restore_drill.sh`):核对空间、库、表、字段、账号和线索条数(括号里是线上的数),看附件包能完整
读出,最后连同数据卷删掉临时数据库。最后一行是"恢复演练通过"才算过;备份日志里有 ERROR、WARNING 的照提示处理。

### 更新 Teable

版本按摘要固定在 `/opt/teable/.env` 的 `TEABLE_IMAGE`(`pin_from_mac.sh` 记下当时运行的版本,见下面「新版」阶段 A),
`docker compose pull`、重跑 `push_from_mac.sh` 都不会再换版本。要升级时手动:

```bash
cd /opt/teable && bash backup.sh
sed -i 's#^TEABLE_IMAGE=.*#TEABLE_IMAGE=ghcr.io/teableio/teable:<新版本>#' .env && docker compose pull teable && docker compose up -d teable
```

升级后在 Mac 上重跑一次能力核验(`scripts/teable_probe.py`,见下面),各项还是 ✓ 再让后台任务用;不对就把 `TEABLE_IMAGE` 改回
`teable_versions.log` 里记的上一个摘要、`docker compose up -d teable`。还没固定过的主机,`docker compose pull` 会拉最新版。
只想做例行检查时用 `check_from_mac.sh`。看日志:`docker compose logs --tail 200 teable`。
装了系统的,更新表格以后跑一次 `check_from_mac.sh`:系统认人靠表格的 `/api/auth/user` 与登录 cookie `auth_session`,
表格改了这两处,检查里"没登录打开 /app/""表格的 /api/auth/user""系统能登录"几项会报出来。

### 真要恢复数据(数据坏了、误删了)

1. 在主机上(`ssh -t` 登录,root):
   ```bash
   bash /opt/teable/restore.sh                                  # 列出现有的备份,新的在前
   bash /opt/teable/restore.sh /opt/teable/backups/db-<时间>.sql.gz
   ```
   脚本先校验数据库备份和同一时间的附件包,都完好才动线上;输入 YES 确认后停表格、换数据库与附件、清缓存(所有人要重新登录)、
   再起表格。装了系统的,系统也先停着(它每 30 秒同步,不先对齐就会把备份里的旧值当成同事改的拉回),并留下记号
   `/opt/teable/restore_pending`,每天 09:30 的自动更新见到它也不起系统。最后打印这份备份的时间。
2. **马上**(没装系统的,在下一次定时任务即北京时间 08:30 之前):Actions → monitor → Run workflow,「表格刚从备份恢复时填备份时间」
   一栏填上一步打印的时间。恢复到这一步跑完之间,请同事先别在表格里改。对齐跑完(那次运行绿了),装了系统的起系统:
   `rm -f /opt/teable/restore_pending && cd /opt/teable && docker compose --profile app up -d app`(脚本最后也打印了这一行)。
   - 为什么要对齐:表格恢复以后,人管字段是备份时的旧值;不先对齐的话,拉回会把它们当成同事改的,把系统也改回去、记下没发生过的操作。
   - 对齐改什么:只改"备份以后系统知道了新值、表格里还是旧值"的格,改回上次同步时的值,不记操作。
   - 对齐不改什么:恢复以后有人改过的格(看记录历史)不改,留给拉回;重跑、时间填早了也不会覆盖。
   - 找不回来的:备份以后同事改了、系统还没拉回的,本来就不在备份里。
   - 对齐没成(读不到库成员或记录历史等)时,这次不拉回也不推送,运行标红;在下一次定时任务之前重跑,填同一个时间。
3. 备份以后新出现的线索,下次推送时重建,但负责人、下一步、到期、结果原因不会跟着回来;对齐的日志列出这些线索的编号,
   请在表格里照操作记录重填。备份以后记的跟进(拉回过的、系统推上去的)对齐时记下,下次推送按系统里的重建;每日摘要的行系统里都有,
   表格里没了;上传的报告下次推送时重传。

### 令牌轮换(令牌在聊天、邮件、截图里出现过,或管理员换人时)

1. 用管理员账号登录表格,打开 `https://<域名>/setting/personal-access-token`(头像菜单 → 设置 → 个人访问令牌),点「osint-water sync」
   → 「重新生成令牌」。**有效期选「永久」**(选 7、30 天的,到期后定时任务就连不上),复制新令牌(只显示这一次)。旧令牌立即失效。
2. GitHub 仓库 → Settings → Secrets and variables → Actions → `TEABLE_TOKEN` → Update,粘贴新令牌。
3. 本机界面「设置与同步 → 团队表格」粘贴新令牌、保存(或改程序目录 `.env` 的 `TEABLE_TOKEN`)。装了系统的,
   在 Mac 上 `ASK_TOKEN=1 bash deploy/teable/app_from_mac.sh <密钥> <主机IP>`,提示时粘贴新令牌(模型密钥直接回车)。
4. 主机上 `/opt/teable/ADMIN.txt` 里的旧令牌已经没用,删掉那一行:`sed -i '/^接口令牌/,+1d' /opt/teable/ADMIN.txt`。
5. Actions → monitor → Run workflow 跑一次,「从 Teable 拉回」「同步到 Teable」两步正常即可。

### 换域名

1. 在新域名的 DNS 里加一条 A 记录指向主机 IP(Cloudflare 的话关掉橙色云朵,只用 DNS)。
2. 在 Mac 的核心仓检出里:`git pull && bash deploy/teable/domain_from_mac.sh <密钥文件.pem> <主机IP> <新域名>`。
   DNS 没生效时脚本停下、什么也不改;生效了就改 `.env` 的 `TEABLE_HOST`、`PUBLIC_ORIGIN`(先备份),旧域名写成
   `caddy.d/old-<旧域名>.site` 整站 301 转到新域名,重建 Caddy 与表格两个容器(数据在卷里不动),最后从主机上自检。只开一个 ssh 连接,可以重复运行。
3. 每个人在新域名重新登录一次(登录 cookie 跟着域名走)。旧书签、旧的日历订阅链接经 301 转到新域名,订阅令牌与域名无关,不用重新订阅。
4. Mac 上表格工具用的 `TEABLE_URL` 改成新域名。后台任务走容器内网 `http://teable:3000`,不用动。
5. 登录邮箱只是帐号名(主机没配邮件,不往里发信),换不换都不影响登录;要换就新建帐号(邀请链接)或在表格的帐号设置里改。

### 迁移到新主机(D4:现在的主机 2026-10-28 到期,到期前定)

选一个不在定时任务前后的时间(比如北京时间晚上),先通知同事:迁移期间(约一小时)表格只看不改,改了的会丢。

1. 新主机:香港或海外节点,2 核 4 GB 起;安全组放行 22(只对自己的 IP)、80、443。
2. 旧主机上备份一次,把这份备份与配置取回 Mac(`.env` 里有数据库密码与密钥,`ADMIN.txt` 里有管理员密码与令牌:只放在这个
   私密目录,不进仓库、不进聊天)。`-p` 保留文件时间(恢复时据此打印备份时间):
   ```bash
   K=~/.ssh/<密钥>.pem; OLD=root@<旧IP>
   ssh -i $K $OLD 'bash /opt/teable/backup.sh'        # 最后一行写着这次的文件 db-<时间>.sql.gz
   T=<上一行里的时间,如 2026-10-20-2130>
   mkdir -m 700 -p ~/teable-move
   scp -p -i $K $OLD:/opt/teable/.env $OLD:/opt/teable/ADMIN.txt $OLD:/opt/teable/backups/db-$T.sql.gz $OLD:/opt/teable/backups/assets-$T.tgz ~/teable-move/
   ```
3. 先把 `.env`、`ADMIN.txt` 放到新主机(数据库密码、SECRET_KEY 不变,登录和接口令牌照旧;安装脚本看到它们不会另建管理员),
   再装(域名不变就写原域名;换域名写新域名,脚本会改 `.env` 里的地址),最后把备份放进新主机的 backups:
   ```bash
   NEW=root@<新IP>
   ssh -i $K $NEW 'mkdir -p /opt/teable/backups && chmod 700 /opt/teable'
   scp -p -i $K ~/teable-move/.env ~/teable-move/ADMIN.txt $NEW:/opt/teable/
   ssh -i $K $NEW 'chmod 600 /opt/teable/.env /opt/teable/ADMIN.txt'
   bash deploy/teable/push_from_mac.sh $K <新IP> <域名>
   scp -p -i $K ~/teable-move/db-$T.sql.gz ~/teable-move/assets-$T.tgz $NEW:/opt/teable/backups/
   ```
4. 在新主机上恢复:`ssh -t -i $K $NEW bash /opt/teable/restore.sh /opt/teable/backups/db-$T.sql.gz`,记下最后打印的备份时间。
5. Cloudflare 里把 A 记录改到新 IP(仅 DNS,灰云),几分钟后 Caddy 自动签证书。换了域名的,GitHub Secrets 的 `TEABLE_URL` 与本机
   「设置与同步 → 团队表格」的地址一起改;表格里的「表格链接」下次推送时自动换成新地址。
6. Actions → monitor → Run workflow,「表格刚从备份恢复时填备份时间」填第 4 步的时间(迁移期间没同步过的话对齐不改任何东西,
   同步过的也能对齐);浏览器登录看几张表;`check_from_mac.sh` 对新主机跑一次(最后一行"恢复演练通过")。通知同事可以改了。
   新主机上还没装系统,第 7 步装好系统以后它才开始每 30 秒同步(装之前先删掉恢复留下的记号 `/opt/teable/restore_pending`)。
7. 装了系统的:新主机上跑一次 `app_from_mac.sh`(会生成新的部署密钥,按提示加到 GitHub,并在 Deploy keys 里删掉旧主机的那把;
   模型密钥重新输入)。程序与配置都在 GitHub 上,`/opt/osint-water`、`/opt/osint-water-private` 不用备份、不用搬;旧主机的 `app.env`、`deploy_key*` 不带走。
8. 旧主机到期不续;到期前可以留着作备查。删 `~/teable-move`。

## 新版(一个库)的准备:阶段 A–C

按 [docs/架构方案_2026-10-03.md](../../docs/架构方案_2026-10-03.md) 第 8 节。**只动新库「水务项目机会 新版」**,旧库与现在的系统照常运行到切换那天

   看板拖动与评论通知要人在界面里看:`--keep --mention <同事显示名>` 留下试验表,拖一张看板卡片、问同事收没收到通知。

   「osint-water 后台」:空间选本空间;权限只要 空间·读、库·读、表·读、字段·读、视图·读、记录·读/新建/更新、评论(**不要**删除、

   - 存进 GitHub:仓库 → Settings → Secrets and variables → Actions → New repository secret,名字 `TEABLE_BOT_TOKEN`。

打开新库看一眼七张表与视图,截图。

`--dry-run` 不写表格,只出对账报告(各表条数、旧库比数据分支多出的线索的来历、对不上的地方、迁移时的取舍);对账没有问题再去掉
`--dry-run` 写进新库。可重复运行(按线索号、商机编号等增量,不重复建;已有的行只补空字段)。行靠内容识别,同事改过的行再跑会重复建,
所以重复运行(含 `--sync`)只在切换前、同事还没用新库时;阶段 F 的增量迁移在冻结旧系统之后、通知同事之前做一次。旧操作记录里的操作人 `admin` 是管理员当时的
表格显示名(使用方 2026-10-03 确认),所以带 `--alias admin=<显示名>`;报告里还有别的对不上岗位代号表的,照样加 `--alias 旧名=表格显示名`。
国别的「市场分级」迁移只填市场 / 其他,「重点」由同事在表格里改(视图「重点国」按它筛)。报告贴回来交审查(审查门 1)。

## 安全

- 主机的 root 密码如果在聊天、邮件里出现过,立刻在云控制台重置;能用密钥登录后,建议关掉密码登录
  (`/etc/ssh/sshd_config` 里 `PasswordAuthentication no`,`systemctl restart sshd`)。
- 不用宝塔面板就在安全组里关掉 8888 端口;要用也只对自己的 IP 开。
- 接口令牌只放 GitHub Secrets、本机 `.env`(已在 .gitignore)与主机上只 root 可读的 `ADMIN.txt`、`app.env`,不进仓库、不进聊天。
  在主机上排查时别把 `docker compose config` 的输出贴出去:它会把 `app.env` 里的密钥展开显示。
- 系统(装了的话):容器不对外开端口,只经 Caddy 进来;认人只信系统自己向表格查到的身份。部署密钥(`/opt/teable/deploy_key`,
  只 root 可读)对这个仓库**可写**——系统要推送人工入库与台账改动;主机被人拿下时,他也能往仓库推代码,所以主机的登录照上面收紧,
  主机换掉或不用系统时,在 GitHub 的 Deploy keys 里删掉这把密钥。
- 人工入库的网址由系统在主机上抓取:系统进程只连公网地址(表格除外),网址本身、对方网站的跳转、页面上的附件链接指向内网、本机、
  云主机元数据的都不连(提示改用"粘贴文字")。git(推送拉取)不经这道检查,只连 GitHub。
- 表格账号就是系统账号:能登录表格的人都能进系统、看全部页面(含内部报告)。给外部的人开表格账号之前想清楚。
- 登录页是公开的:上面的字体、标志、首页视频与封面没登录也能打开(只这几个文件,`portal.caddy` 的 `@ow_open`)。首页视频因此等于公开,别放不想外传的片子。
- 操作记录里的代号按表格显示名换:同事把显示名改成别人的名字,记录里会记成别人的代号(权限不受影响:管理员按邮箱认;
  表格自己的修改历史记的是真账号)。
- 登录主机用的 `.pem` 密钥放在 `~/.ssh/`(`chmod 600`),不要放在程序目录或"下载"里;仓库的 .gitignore 已排除 `*.pem`,
  但放在 `~/.ssh/` 才不会被随手打包、同步到网盘。
- 数据在境外主机上:线索是公开招标信息;商机表的「优先级」「负责人」「内部备注」由同事在表里填写(每天拉回 `private/overlay`),
  内部叠加里的优先级与 `note`(内部备注)也会写到表格,请只写团队需要共享的内容;overlay 里的其余判断(角色、判断依据、
  非公开情报)不推送到 Teable。跟进记录、结果原因同样只写需要共享的。「报告」表缺省只有周报与月报公开版;月报内部版
  (内部叠加的判断与非公开信息)、国别动态与线索简报(市场分布表里的区域与我方在该国的情况)只在 profile 打开
  `teable.internal_reports` 时才传,打开前先确认这个库只有该看的同事能进。
