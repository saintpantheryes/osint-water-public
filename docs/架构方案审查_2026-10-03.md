## 二、建议改(在相应阶段做)

1. **最晚启动**(§3 派生字段):公式放在时间节点表(每个节点 = 日期 − 该类型的内部流程周期),商机取未来节点里最早的汇总;比在商机上用两个条件查找再 IF 简单、可读。
2. **部分日期取起点**的约定写明:截止类取起点偏保守(最晚启动更早),可接受;日历与表里同时显示「日期原文」。
3. **运行告警**:worker 挂了没人知道。每次采集成功后 ping 一个免费的 dead-man's switch(healthchecks.io 之类),或至少规定信源「异常」视图每天有人看;写进阶段 D 验收。
4. **并行期**:阶段 D 实跑一整天时,旧 GitHub 定时监测要先停(改手动)或错开时间,不要两套程序同时抓同一批信源。
5. **跟进记录主字段**:长文本未必能做主字段,用公式"日期 · 记录人 · 内容前 40 字";阶段 A 顺带核验。
6. **编辑者能删记录**:《表格使用说明》写"线索不删、只标已忽略"(删了机器会重采);Teable 有回收站可恢复。
7. **回退**(§8-F)补一句:回退后,切换期间新库新增的数据不回流旧系统;阶段 C 的 28 条差异结论要在审查门 1 之前定下,不能带着差异迁。
